# TSH-002 - Fixing Ollama Context Window Blindness

This operational guide provides the troubleshooting protocols for resolving "Context Blindness" and prompt overflows when running context-heavy coding assistants against local Ollama models on resource-constrained hardware [497].

---

## Problem Description & Symptoms

**Context Blindness** occurs because Ollama enforces a conservative default context window limit of **2,048 tokens** (or 4,096 tokens depending on system triggers) to protect low-end systems from crashing [497]. 

When executing multi-file coding agents (such as Claude Code or Cursor) against Ollama, the prompt payload instantly overflows this default limit [497]. To accommodate the incoming tokens within its narrow window, Ollama *silently discards* the oldest files and historical context fed to it [497]. As a result, the coding assistant becomes instantly blind to critical parts of the codebase [497].

### Hardware Context
Resolving this issue on a **16 GB RAM / CPU-only laptop** requires balancing the context depth against the physical memory footprint [497]. Expanding the context window increases the RAM consumed by the KV Cache (the model's short-term working memory) [497].

---

## Resolution Strategies

The complete engineering playbook to resolve Context Blindness on standard local hardware comprises three primary approaches:

### Strategy 1: The Modelfile Fix (Highly Recommended)

The cleanest and most robust method to permanently expand the context window is to configure the limit directly within a custom version of your local model using an Ollama Modelfile [498]. For standard 16 GB RAM specs, upgrading the context window to **8,192 tokens (8K)** represents the optimal balance, providing enough memory to digest multiple code files simultaneously without overloading the system's available RAM (approx. 5.7 GB free) [498].

#### Implementation Steps:
1. Open **Notepad** [499].
2. Point the file to your current local base model and set the `num_ctx` parameter permanently [499]:
   ```dockerfile
   FROM qwen2.5-coder:latest
   PARAMETER num_ctx 8192
   ```
3. Save the Modelfile as **`Qwen8k.Modelfile`** inside your **`C:\OllamaModels\`** directory [499].
4. Open the Windows **Command Prompt** (or PowerShell) and build the expanded model [499]:
   ```cmd
   ollama create qwen3b-8k -f C:\OllamaModels\Qwen8k.Modelfile
   ```
5. Configure your local AI client or agent extension to select **`qwen3b-8k`** instead of the original base model [499].

---

### Strategy 2: The Global System Variable Fix

If you prefer that **all** executed Ollama models dynamically utilize an expanded context cushion without requiring the creation of custom Modelfile duplicates, you can define a global Windows Environment Variable [499, 500].

#### Implementation Steps:
1. Press the **Windows Key**, search for **Environment Variables**, and select **Edit the system environment variables** [500].
2. Click the **Environment Variables...** button in the bottom right corner [500].
3. Under **User variables for [YourUsername]**, click **New...** [500].
4. Set the fields exactly as follows [500]:
   * **Variable name:** `OLLAMA_CONTEXT_LENGTH`
   * **Variable value:** `8192`
5. Click **OK** on all dialog boxes to save the configurations [500].
6. **Apply Changes (Crucial):** Right-click the Ollama icon in your Windows System Tray (taskbar, bottom right corner), select **Quit**, and then re-launch the Ollama desktop application to initialize it with the new environment rules [500].

---

### Strategy 3: Codebase Pruning & Scoped Execution

Even with an expanded 8K context window, automated context-gathering tools can easily exhaust limits if they blindly index large directories [501]. Enforce the following developer workflow best practices to prevent context bloat [501]:

* **Repository Filtering:** Ensure your context packaging or indexing tools respect exclusion filters (like `.gitignore` or `.pkp-root` configurations) to skip massive autogenerated folders such as `/bin`, `/obj`, `.git`, or heavy `node_modules` folders [312, 501].
* **Scoped Execution:** Instead of initializing the coding agent at the absolute root of a massive multi-project solution directory, launch your terminal window directly inside the specific target project subfolder (e.g., `cd MySolution/MyWebAPI`) containing only the active controllers, scripts, or schemas you are modifying [312, 501].
